# 13 — Landscape Lee, phone stuck sideways for the whole evening browse
**Device:** Mobile landscape 844x390 (rotation lock broken, whole session sideways) · **Goal:** Browse, find some joggers, buy them without the layout falling apart · **Mood:** Mildly annoyed at the phone, not at the shop — yet

### Step 1 — Landed on the homepage sideways
**Did:** Opened the site in landscape. / **Got:** Ticker + header on top, then a huge COOKIE CONSENT sheet rising from the bottom — it covers the lower half of my 390px screen (197px tall, from y=193 down). The Manage preferences / Accept / Decline buttons sit in a neat row at y=324 and are all tappable. (Harness note: Shopify's own preview bar overlaid the buttons and blocked the first click — that is a preview artifact, not the store; it was stripped for the rest of the session.) / **Expected:** A cookie bar hogging the short screen. / **Felt:** "Half my screen is cookie form, but at least the buttons are on-screen and in one row. Accept, move on." / **Next:** Accept.

### Step 2 — The Getaway popup, sideways
**Did:** Waited a beat after accepting cookies. / **Got:** "CROOKSLDN: THE GETAWAY — Crack the cuffs. 10% off your first order — code sent by text. Attempts unlimited. RUN IT / NOT NOW." The card is 520px wide, 440px tall — in a 390px-tall viewport its bottom edge sits ~58px below the fold. Title, copy, RUN IT and NOT NOW are all visible; only the "One code per player." fine print hugs the very bottom edge and the card border is cut. The overlay does scroll (66px of hidden content) but nothing tells you that. There are two close X's — one inside the card, one floating at the top-right of the screen. / **Expected:** A popup that breaks in landscape. / **Felt:** "Actually… it fits. Cheeky pixel-font energy. Fine, I'll play." / **Next:** RUN IT.

### Step 3 — Playing the game in a 390px-tall window
**Did:** Hit RUN IT. / **Got:** A second screen (inside an embedded frame): "CRACK THE CUFFS. Three tumblers. Tap each one at the right moment." with its own RUN IT. Here landscape hurts: the game content is anchored to the bottom of the tall card, so the top ~40% of my screen is empty dark card, and the fine print ("…Code expires in 20 [minutes]") is chopped by the fold. Started the game: "TAP TO STOP", a draining bar, three tumbler buttons (94px tall — easy to hit), "0/3 LOCKED" just above the fold, and the instruction line below it, cut off. Tapped the tumblers, locked 3/3 — "CUFFS OPEN. You cracked the cuffs. Cutting your code." Then — the win screen melted into "CUFFS HOLD. Run it again — attempts are unlimited." My win got eaten. / **Expected:** Win = code. / **Felt:** "Oi. It literally said it was cutting my code, then told me the cuffs held. Which is it?" / **Next:** Run it again (attempts unlimited, apparently for the machine too).

### Step 4 — Second run: the code, and a scare
**Did:** Played again, tapped each tumbler once. / **Got:** "CUTTING THE CODE…" then the evidence card: EVIDENCE Nº GTWY-6FWC, 10% off, one use. But for the first second it rendered "CODE EXPIRED" in red with a greyed-out EXPIRED button before flipping to "Expires in 19:59" + a working COPY CODE. Also: the intro promised "code sent by text", yet the code just appears on screen — the phone number is optional ("Want it kept on file? … FILE IT", tel field placeholder 07XXXXXXXXX). In landscape that phone field and FILE IT sit below the fold; the code and COPY CODE are what you see. I did not enter any number — noted the ask and closed. / **Expected:** To be forced to hand over my number for the code. / **Felt:** "Flashing CODE EXPIRED at me before I've even read the code is a small heart attack. But respect: code on screen, number optional. Writing down GTWY-6FWC." / **Next:** Actually shop.

### Step 5 — Homepage and catalogue, sideways
**Did:** Dismissed the popup, scrolled the homepage, tapped SHOP → ALL. / **Got:** The layout holds. No horizontal scroll anywhere (page width stays 844). The ticker (28px) + header (61px) stay stuck on top — 89px, roughly a quarter of my 390px screen, so I browse the world through a ~300px letterbox. The evidence-strip and "SUBJECT WEARING: PRODUCT: REDACTED" boards render fine. Catalogue: FLAT / ON MODEL toggles, category tabs, 13 items in two 405px columns. All usable. / **Expected:** Overlaps and cut-off grids. / **Felt:** "Fair play, it's built like it expected me. Bit of a letterbox with that header always on, but nothing breaks." / **Next:** Open the black joggers.

### Step 6 — Product page: the great scroll
**Did:** Opened BLACK CONVICT JOGGERS (£60). / **Got:** The product photo is 770px tall — nearly two full screens in landscape; I can never see the whole jogger at once. Title, price, size grid land ~3 screens down. Size buttons XS–XL (72x52, all in one row, easy taps), the add button reads SELECT SIZE and is disabled until you pick — clear. Picked M, ADD TO BAG. Inline confirmation: "> Added — 1 in bag  View bag", and BAG [1] in the header. No drawer flying in, no sticky buy-bar appears in landscape — nothing eats the bottom of the screen, but also nothing follows you back up. / **Expected:** A sticky bar covering half the short viewport. / **Felt:** "Scrolling past that photo took ages sideways, but the buy bit behaves. The little '> Added' line is quietly classy." / **Next:** Bag.

### Step 7 — Cart: checking the old wound
**Did:** Went to the cart, looked hard at the line item (run 1 reportedly had the title printed over the thumbnail in landscape). / **Got:** Clean. Thumbnail 88x110 at x=40–128, title "BLACK CONVICT JOGGERS" starts at x=142 — a 14px gap, zero overlap. Two-column cart: items left, Discount + Estimated total right. Quantity +/− and Remove are all 44x44. Free-shipping meter reads "£20.00 to free Tracked 24" with TRACKED 48 FREE already ticked — took me a second to square that with the header's "free UK shipping over £30" (two tiers, fine, but sounds contradictory at a glance). / **Expected:** The overlap bug. / **Felt:** "Whatever was mangled before, it's fixed. This cart is tidier than my portrait apps." / **Next:** Try my code.

### Step 8 — The code works… then checkout ghosts it
**Did:** Opened Discount, typed GTWY-6FWC, applied. Then hit Check out. / **Got:** Cart: "GTWY-6FWC −£6.00, Estimated total £54.00". Lovely. Checkout landing (standard white Shopify page — bright flip after all that dark): Order summary… £60.00. Expanded it: Subtotal £60.00, Total £60.00, Discount code field EMPTY. My discount evaporated between cart and checkout. Re-typed GTWY-6FWC into the checkout's own field: accepted — "Discount code GTWY-6FWC has been applied… Total £54.00, Total savings £6.00". So the code survives, but only if you notice and re-type it. Stopped at the landing per the rules — no details entered. / **Expected:** The £54 to follow me. / **Felt:** "If I hadn't squinted at that collapsed £60.00 I'd have paid full price after winning their own game. That's a dirty trick even if it's an accident." / **Next:** Done — stopping at the payment step.

## Outcome
**Bought / didn't:** Didn't complete (audit stop at checkout landing) — but got all the way there: M black joggers, code re-applied, £54.00 total, payment step reached. In real life I would have bought.
**Total time:** ~22 minutes
**Worst moment:** Watching my £6 discount silently vanish between cart (£54) and checkout (£60, empty code field) — plus the game eating my first win ("cutting your code" → "CUFFS HOLD").
**Best moment:** The cart in landscape — the old overlap is gone, everything aligned, 44px controls; honestly the whole theme survives 844x390 with zero horizontal scroll.
**Would they come back?** Yes — the layout respects a sideways phone better than most sites respect a normal one. But the discount hand-off and the game's glitchy win/expired flashes need sorting before I'd trust it blind.
**One thing that would have changed the outcome:** Carry the cart-applied discount into checkout automatically (or at least show it in the checkout summary) — that's the difference between £54 and £60 for anyone not paying attention.

### Layout notes at 844x390 (for the team)
- No horizontal overflow on any page tested (home, catalogue, PDP, cart, checkout): scrollWidth stayed 844.
- Sticky ticker (28px) + header (61px) = 89px, ~23% of the viewport, on every page. Tolerable, but it is a letterbox.
- Cookie banner: 197px tall (bottom half of screen); all three buttons on-screen and tappable at y=324.
- Getaway intro card: 520x440 in a 390px viewport — bottom ~58px below the fold (fine print/card edge); overlay scrolls but gives no hint. Game screen content is bottom-anchored, leaving the top ~40% of the card empty in landscape and pushing the instruction line below the fold. Tumbler buttons (94px) fit and are tappable. Win screen: code + COPY CODE visible; optional phone field (FILE IT) below the fold.
- Getaway glitches seen: (1) first win flashed "CUFFS OPEN … Cutting your code" then resolved to the CUFFS HOLD loss screen; (2) code screen renders "CODE EXPIRED"/EXPIRED for ~1s before the 19:59 countdown appears; (3) intro copy still says "code sent by text" though the code is delivered on-screen.
- Cart line item: thumbnail right edge x=128, title starts x=142 — run-1 overlap NOT reproduced (fixed).
- No sticky add-to-bag bar in landscape; buy controls are inline only. PDP hero image 770px tall (~2 viewports of scrolling).
- Cart-applied discount does not carry into Shopify checkout; the code itself remains valid and can be re-typed there ("one use" is not consumed by the cart application).
